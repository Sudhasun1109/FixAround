FixAround — Smart Local Service & Emergency Repair Platform

Project Category: Progressive Web App (PWA) & Hyperlocal Geospatial System
Evaluation Focus: Engineering Quality, Validation & Testing (10M), Novelty (10M), Patent Drafting (15M), Viva & Documentation (10M)

1. Problem Statement & Need

  • Long Waiting Times: Existing apps take 4 hours to 2 days for home repairs. During pressing emergencies (short circuit, water leak), users have no immediate help.
  • Hidden & Unfair Pricing: Handymen quote arbitrary prices after visiting without any fixed price list or part breakdown.
  • Safety & Verification Risks: Unorganized local workers lack police verification, government KYC checks, and live GPS tracking.
  • Worker Payment Insecurity: Technicians face delayed payouts, high platform commission cuts (up to 30%), and frequent cash defaults.

2. Proposed Solution

FixAround is an installable Progressive Web Application (PWA) connecting households with verified nearby technicians in real time.

  • Instant Emergency Dispatch: Nearest technicians receive a 2-minute countdown timer to accept urgent tasks.
  • Live GPS Telemetry: Customers track the technician's real-time approach on an interactive map.
  • Pre-Job Digital Estimates: Mandatory digital quote (labor + materials) approved by the customer before work starts.
  • Two-Tier Escrow Settlement: Customer payment is held safely until customer OTP confirmation and Admin verification.
  • Automated 30-Day Warranty: Every completed job receives an in-app digital warranty card.

3. Novel / Innovative Features

  1. 120-Second Auto-Cascade: If a technician fails to accept within 2 minutes, the job automatically cascades to the next nearest peer.
  2. Two-Tier Admin Escrow: Customer pays $\rightarrow$ Funds held in escrow $\rightarrow$ Customer confirms via OTP $\rightarrow$ Admin verifies $\rightarrow$ Funds released to technician.
  3. Dual-Factor Completion OTP: Technicians cannot mark a job done without the customer's secret OTP.
  4. Loyalty Rewards & Wallet: Earn 20 points per job. Every 5 points equals ₹1 deduction on subsequent bookings.
  5. Installable PWA (<2 MB): Fast, app-like experience on any phone or desktop without app store installation.

6. Product Development & Engineering Quality

Development Stages Completed

  1. Database Modeling: Normalized relational schema on TiDB Cloud Serverless MySQL.
  2. REST API & Security: Built with Node.js/Express, JWT auth, Helmet headers, and rate limiting.
  3. Real-Time Telemetry: Socket.IO rooms for live coordinate streaming and 120-second timers.
  4. PWA Client: React 18 SPA styled with Tailwind CSS, Lucide icons, and Service Worker caching.
  5. Payment Subsystem: Razorpay Orders API integration with HMAC-SHA256 signature verification.
  6. Cloud Deployment: Production hosting on Render cloud with TLSv1.2 database encryption.

Key Technical Specifications

Frontend: React 18, Vite 5, Tailwind CSS, Leaflet OpenStreetMap.
Backend: Node.js 18+ LTS, Express 4.x, Socket.IO, express-validator.
Database: TiDB Cloud Serverless (MySQL 8.0 wire-compatible, Port 4000, TLS 1.2).
Payments: Razorpay SDK, Escrow holding mechanism, In-app Virtual Wallet.

Engineering Challenges & Solutions

  • Cloud TLS Connection Crash: Fixed TiDB insecure transport error by enforcing TLSv1.2 with Node.js root CA bundle verification.
  • Stale Technician Locks: Built automated background worker to cancel expired 120s dispatch locks and reassign instantly.
  • Double-Spend in Wallet: Applied database row-level locking (SELECT ... FOR UPDATE) during wallet mutations.

12. Documentation & Viva Defense (10 Marks)

  • Q1: Why choose a PWA over a native mobile app?
    Answer: PWAs require less than 2 MB of storage, install instantly without App Store friction, run universally on all devices, and avoid 30% app store commission fees.
  • Q2: How does FixAround prevent payment fraud?
    Answer: Customer payments are held in an Escrow vault. Money is only transferred to technicians after the customer provides the completion OTP and the Admin verifies the completed job card.
  • Q3: What happens if a technician ignores an emergency dispatch?
    Answer: The request has a strict 120-second timer. If unaccepted, the backend cron worker auto-cancels the allocation and cascades the job to the next nearest certified technician immediately.
